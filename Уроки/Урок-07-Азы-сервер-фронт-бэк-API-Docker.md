### 🔑 Главные идеи
- Агент = LLM (модель: Sonnet, Gemini, Fable и т.д.) + инструменты (скиллы, MCP) + память + цикл. Чат только отвечает на вопросы, а у агента есть «руки», и он доводит задачу до результата.
- Цикл агента — это не бесконечная работа: вы ставите цель, а агент сам повторяет попытки, пока её не достигнет. Цикл нужно ограничивать: лимит кругов, условия остановки и критерии успеха (Definition of Done).
- Claude Code CLI в терминале — «голый» и самый сильный вариант: меньше внутренних ограничений, обновления приходят туда первыми, команды тратят меньше токенов, и можно запускать много агентов параллельно. Claude Desktop больше подходит для автоматизаций и рутины (cron).
- VS Code нужен, чтобы видеть «под капотом», какие файлы и скиллы создаются: результат работы агента всегда должен проверять человек.
- Фронтенд — это зал (всё, что видит клиент), бэкенд — кухня (логика, оплата, проверки), API — официант между ними, база данных — склад, сервер — здание, домен — адрес, Docker — коробка, в которой всё здание можно перенести.
- RAG — это приём, а не скилл: документы режут на смысловые куски и ищут по смыслу, а не по словам. Он нужен, когда ИИ в вашем продукте должен отвечать по вашим данным.
- Harness — вся настроенная среда для агента: память, инструменты, правила, система работы (как этапы в Superpowers). Повар без ножей и плиты работать не сможет, так и агент без Harness.
- Код ИИ пишет лучше и быстрее человека, но направлять работу (архитектура, Harness) и проверять результат должен человек.
- Демо «всегда работает», но для продакшена нужны правильная среда, свой сервер, CI/CD и защита — иначе проект ломается, лагает или его взламывают.

### 🛠 Что показали на практике
- Скилл «вайбкодинг-ментор» (вторую версию обещали выпустить после урока): сам ставит дополнительные MCP, Docker, подключается к Hetzner через CLI.
- Если Claude отвечает на английском, добавьте в `CLAUDE.md` правило «всегда отвечай на русском простым языком».
- Схемы преподаватель рисует в Excalidraw. Для студентов дали Miro MCP: в чате пишете «Создай мне схему», и ИИ рисует её сам. Ещё один MCP для схем ставится вместе с ментором, чтобы агент объяснял ответы блок-схемами.
- Claude in Chrome — обязательный инструмент.
- Docker Desktop: агент сам поднимает контейнеры. Не пугайтесь, если запустится какая-то программа.
- Lottie Creator (MCP) — для анимаций на сайте: загрузочные экраны, 2D- и пиксельные анимации.
- Плагин claude-code-setup ставится через маркетплейс плагинов (команда есть в презентации). Он сам подбирает MCP, скиллы, хуки, агентов и команды под ваш проект.
- NotebookLM как пример RAG-системы. Есть и open-source аналог, его можно поднять на своём сервере (ссылку обещали скинуть).
- Серверы: Hoster KG (для Кыргызстана), DigitalOcean (дёшево, чтобы попрактиковаться), Hetzner (есть CLI, им будут пользоваться на уроках).
- CI/CD через GitHub Actions: изменение попадает в репозиторий и само выкатывается на сервер. Агенту достаточно сказать «Сделай CI/CD».
- Google Stitch: генерирует экраны, иконки и дизайн-систему. Подключите Stitch MCP и напишите в Claude примерно «сделай мне в Google Stitch дизайн по моей спеке».
- Скилл для RAG в проекте и скилл проверки безопасности (имитирует тысячи запросов и попытки взлома в Docker-копии проекта) обещали выдать позже.

### ⚠️ Ошибки и советы
- «Claude пишет, что в скилле небезопасные скрипты»: это нормально, скрипты просто сами скачивают нужное, а Claude стал осторожнее.
- «Где взять MCP-ключи?» — в профиле своего сервиса, как показывали на первых уроках. MCP-ключи и API-ключи — разные вещи, у каждого пользователя они свои.
- «Ставить через Claude Desktop или через VS Code?» — разницы нет: Claude Code встроен в VS Code. Можно ставить глобально или в проект.
- Если после установки скилла ответы не изменились, скорее всего он не установился. Проверьте, перезапустите или напишите преподавателю.
- Хранить коммерческие или персональные данные у третьих лиц (например, в Supabase) рискованно, а в некоторых странах закон требует хранить их на местных серверах. Поэтому на курсе арендуют свой сервер.
- Студент заметил, что его сайт лагает: запросы шли через Японию и Нидерланды. Базу данных и сервис лучше держать рядом. Так выглядит неправильно настроенная среда.
- Агент может сделать то, о чём его не просили: при деплое переделал UI, придумал 45 лишних таблиц. Оплата работала только в русской версии сайта. Всё это лечится Harness и проверкой результата.
- Graphify находит рискованные места: например, один файл, от которого зависит 25 путей. Это тоже часть Harness.
- Docker при нагрузочных тестах может сильно тормозить даже мощный ноутбук. Не трогайте его, пока процесс не закончится, или поставьте лёгкую версию.
- Вопросы по своему проекту лучше задавать самому Claude: он знает ваш проект.
- App Store требует платный аккаунт Apple Developer (около $100 в год), поэтому на курсе публикуют только в Google Play.
