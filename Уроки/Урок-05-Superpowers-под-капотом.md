## 📒 Конспект по записи
> Урок посвящён плагину Superpowers для Claude Code — набору из 14 скилов и одного хука, который заставляет агента работать по процессу: брейншторм → спецификация → план → проверка идеи в отдельной ветке → разработка субагентами → тесты → сдача. Преподаватели объяснили, зачем это нужно (у агента нет системы и памяти, он «закрывает одну задачу и забывает»), и вместе со студентами установили плагин и запустили его на своих проектах (Азамат делал с нуля маркетплейс фруктов). Во второй половине поговорили о правилах Андрея Карпатого и начали ставить Graphify — граф знаний проекта, чтобы у агента была «память». Из-за медленного интернета в аудитории работу не успели закончить — её задали доделать дома.

### 🔑 Главные идеи
- Человек в разработке с ИИ должен заниматься только ревью — проверкой и приёмкой результата; всё остальное делает агент.
- Главная работа — правильно подбирать и интегрировать готовые инструменты: «умные люди уже всё сделали за нас» (Superpowers скачали около миллиона раз).
- Три принципа Superpowers: агент сам себя тестирует (test driven development), работает по процессу, а не угадывает, и стремится к простоте.
- Перед разработкой нужно «поразмышлять» над продуктом: Superpowers сам задаёт вопросы (брейншторм), т.к. люди обычно пишут плохие промпты вроде «сделай красиво».
- Спецификация (спека) — это договорённость между вами и агентом, обычный MD-файл; по ней строится план, и она обновляется вместе с кодом.
- Благодаря спекам сессии становятся связанными: агент помнит, что и почему он делал, и подстраивается под ваш процесс и команду.
- Без системы агент «делает одну задачу и забывает, зачем»; Superpowers + память решают эту основную проблему вайбкодинга.
- У LLM нет памяти — агент каждый раз читает всё с начала; поэтому нужен граф знаний (Graphify) — «Google для агента» по вашему проекту.
- Субагенты нужны, чтобы делить большую задачу и не забивать контекстное окно основного агента.
- Если можете объяснить свой проект — значит, вы его поняли.

### 🛠 Что показали на практике
- Установка плагина Superpowers: сайт Claude Plugins (официальные плагины Claude Code) → карточка Superpowers → скопировать команду установки → вставить в чат Claude Code («пусть сам делает»). Можно ставить глобально или в проект; на уроке ставили глобально.
- Проверка установленных плагинов: `/plugins` → Manage plugins — в списке должен быть включённый Superpowers. После установки нужно начать новую сессию.
- Открытие проекта: в VS Code «File → Open Folder», работа идёт в панели Claude (а не во встроенном чате VS Code — его можно закрыть).
- Запуск: можно просто описать задачу, а можно явно написать «Используй Superpowers» или выбрать скил через `/superpowers…` в списке команд.
- Признак, что всё работает, — в чате видно запуск скила `superpowers:brainstorming`, затем `superpowers:writing-plans`; в проекте появляется папка с документами (спеки).
- Демо Азамата: маркетплейс фруктов. Агент спрашивал, кто продаёт/покупает, нужны ли реальные платежи, какая цель первой версии (MVP, прототип или демо). Выбран «полноценный прототип без реальных денег».
- Ответ «Да, продолжай» переводит к следующему этапу; можно один раз написать «решай сам», чтобы агент меньше спрашивал.
- На этапе разработки выбирать вариант Subagent-Driven (отдельный субагент на каждую задачу), а не Inline.
- Запуск результата: промпт «Запусти локально то, что ты сделал» — агент поднимает localhost.
- Перенос строки в поле ввода — `Shift+Enter`.
- Правила Андрея Карпатого (скил, набравший миллионы просмотров): думай до кода; простота прежде всего; точечные правки (не трогать то, что не связано с задачей); цель вместо приказа (сначала сделать, потом проверить).
- Graphify: скопировать ссылку на GitHub-репозиторий → новая сессия → «Скачай это на мой компьютер» → запустить `/graphify` в проекте (на вопрос, какую часть строить, выбирать «целиком»). Результат — папка `graphify-out` и HTML-страница с графом. Запускать один раз на каждый проект, дальше агент пользуется графом сам.
- Расход токенов за сессию и неделю: команда `/usage`.
- Обещали скинуть команду для Claude Code, которая проигрывает звук, когда агент закончил работу.

### ⚠️ Ошибки и советы
- «Почему этапы называются не как в классической разработке?» — названия придуманы не преподавателями; по сути: обсуждение → ТЗ (спека) → план → проверка идеи в ветке → разработка субагентами → тест → сдача.
- «Работает ли Superpowers с другими моделями, в т.ч. на своих серверах?» — да, это просто набор скилов.
- Для доработки существующего проекта агенту обязательно нужен доступ к коду; в начале он «будет тупить», пока собирает спеки — это нормально.
- Если дать задачу «проверь/протестируй проект», Superpowers запустит скилы ревью и тестирования, а не брейншторм — это не ошибка, просто другая задача.
- Простые задачи (например, одна HTML-страница без базы) агент делает без плана и декомпозиции — лишние этапы он пропускает, чтобы не тратить время и токены.
- Можно передумать на любом этапе: просто напишите в чат «про тот вопрос я передумал…».
- Появление диалога — ещё не доказательство работы плагина; смотрите, что в чате видно название скила Superpowers.
- Если команда плагина/скила не появляется — перезапустите Claude Code или попросите агента «установи глобально, чтобы я мог запустить эту команду».
- Graphify мало установить — многие его так и не запустили, поэтому графа знаний у них нет.
- Graphify лучше запускать отдельно по проектам (у каждого проекта своя история), данные разных проектов при этом не смешиваются.
- Если в проекте 90 субагентов — это слишком много; лучше выбрать вариант поменьше.
- Если закрыть Claude Code посреди работы, процесс остановится — потом напишите «продолжай», и агент разберётся, где остановился.
- Совет для проектов в продакшене: настроить уведомления об ошибках (в Telegram или через сервис мониторинга), потому что баги бывают у всех; помнить, что понравившийся проект могут скопировать или атаковать.
