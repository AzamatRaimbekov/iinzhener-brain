# Первый запуск: бриф и подключения

Читается, когда `config/profile.json` отсутствует — значит скилл у нового
человека и его надо настроить. Задача этого файла: провести человека от «у меня
ничего нет» до готового профиля, ничего не выдумав за него.

Тон разговора — как у коллеги, а не анкеты. Спрашивать по одному-два вопроса
за раз и объяснять, зачем это нужно. Человек может не знать, что такое
digital twin или почему важна вертикаль.

## Шаг 1. Бриф

Пять вопросов. Ответы определяют всё остальное.

1. **Кто в кадре?** Свой ИИ-аватар, аватар другого человека с его разрешения,
   или аватара ещё нет. Если нет — переходим к шагу 3, его надо создать.
2. **На каком языке** будут ролики.
3. **Куда публикуем** — Reels, Shorts, TikTok. От этого зависит формат
   (обычно 9:16) и безопасные поля: у Instagram нижние 35% высоты перекрываются
   интерфейсом, и субтитры туда опускать нельзя.
4. **Есть ли уже свой стиль субтитров** — шрифт, цвет акцентов, привычки.
   Если есть опубликованные ролики, лучше замерить по ним, чем спрашивать
   абстрактно: скачать пару штук и посмотреть, как там сделаны титры.
5. **Чьи вставки** будем использовать в клонах: кадры референса как есть,
   искать свои по правам, или генерировать. Это решение владельца, не наше —
   у него могут быть свои договорённости и риски.

## Шаг 2. Проверить инструменты

Что должно быть на машине. Проверять командой, а не спрашивать:

```bash
which yt-dlp ffmpeg ffprobe whisper-cli
python3 -c "import PIL; print('Pillow', PIL.__version__)"
ls ~/whisper-models/ 2>/dev/null
```

| Инструмент | Зачем | Если нет |
|---|---|---|
| `yt-dlp` | скачать референс | `brew install yt-dlp` |
| `ffmpeg` / `ffprobe` | вся сборка и замеры | `brew install ffmpeg` |
| `whisper-cli` + модель | пословные таймкоды | `brew install whisper-cpp`, модель `ggml-large-v3-turbo.bin` положить в `~/whisper-models/` |
| Pillow | рисование субтитров | `pip3 install Pillow` |

У ffmpeg часто нет фильтра `drawtext` — поэтому субтитры и рисуются через
Pillow отдельными картинками. Это не костыль, а обход реального ограничения.

## Шаг 3. Подключить HeyGen

Аватар генерируется через официальный MCP HeyGen. Эндпоинт:

```
https://mcp.heygen.com/mcp/v1/
```

Подключение — OAuth, ключ никуда вводить не надо:

```bash
claude mcp add --transport http heygen https://mcp.heygen.com/mcp/v1/
```

Дальше в интерактивном терминале `/mcp` и вход в HeyGen в браузере.
Важно: **MCP-серверы подхватываются при старте сессии**, поэтому после
подключения сессию надо перезапустить, иначе инструментов не будет видно.

Проверить, что доступ живой и есть кредиты:
- `get_current_user` — план и остаток
- `list_avatar_looks` — образы
- `list_voices` с `type: "private"` — свои голоса

### Если аватара ещё нет

Аватар и голос создаются в кабинете HeyGen, не из скилла. Что сказать человеку:

- снимать надо **одним непрерывным дублем**, без монтажных склеек: обучение
  падает с ошибкой «Multiple scenes detected»;
- голову держать ровно, без резких поворотов — вторая частая ошибка
  «Large face angle»;
- для вертикальных роликов снимать **портретно** и желательно 720×1280 и выше:
  горизонтальный исходник в вертикали придётся растягивать;
- голос можно клонировать внутри HeyGen либо подключить внешний из ElevenLabs.
  Внешний звучит богаче, но зависит от чужой подписки: если она кончится,
  рендер упадёт с `VOICE_ACCESS_RESTRICTED`, хотя кредиты HeyGen будут целы.

### Если голос берётся из ElevenLabs

Отличить внешний голос от нативного можно по ответу `get_voice`:
у внешнего `preview_audio_url` пустой и `language` — `unknown`, потому что
HeyGen не хранит его сэмпл у себя.

## Шаг 4. Подобрать кадрирование аватара

Один раз на аватар. Нужно, чтобы в сплите лицо целиком помещалось в нижнюю
половину, а макушка вставала сразу под швом.

```bash
ffmpeg -ss 3 -i avatar.mp4 -frames:v 1 \
  -vf "drawbox=0:830:1080:4:red@0.9:t=fill,scale=360:-2" proba.jpg
```

Посмотреть, где красная линия пересекает лицо, и подобрать `crop_y` / `crop_h`
в профиле так, чтобы в нижнюю половину попали голова и плечи.

## Шаг 5. Записать профиль

Скопировать `config/profile.example.json` в `config/profile.json` и заполнить
по результатам шагов. После этого скилл работает как обычно.

## Шаг 6. Пробный ролик

Не начинать с длинного. Взять короткий референс либо только первые 15 секунд
длинного: там обычно есть все композиции и оба типа субтитров. Показать
результат владельцу и поправить стиль до того, как собирать минуту.

На пробном ролике решаются два вопроса, которые иначе всплывут поздно:
какой движок аватара выбрать (`avatar_iv` спокойнее, `avatar_v` выразительнее)
и не кажется ли речь медленной.
