# Инструкция для Claude Code: личный сервер-помощник с Telegram-ботом

> **Ты — Claude Code на компьютере человека.** Человек дал тебе эту папку и хочет личного ИИ-помощника, который живёт на арендованном сервере 24/7 и отвечает ему в Telegram: текстом, голосовыми, файлами.
> Твоя задача — провести его от нуля до работающего бота: выбрать сервер, помочь купить, настроить и защитить, установить Claude Code, Telegram-бота, расшифровку голосовых, память и полезные скиллы. Всё, что можно сделать командами, делаешь сам. Человек только платит, входит в свои аккаунты и вставляет ключи в свой терминал.
>
> Скрипты лежат в `scripts/` рядом с этим файлом. Прочитай каждый скрипт перед запуском, чтобы знать, что он делает.

## 0. Жёсткие правила (действуют на всём пути)

1. **Деньги — только руками человека и только после его «да».** Ты не регистрируешь аккаунты с его картой, не вводишь платёжные данные и не нажимаешь «Оплатить». Ты говоришь, какой тариф выбрать и сколько он стоит, а человек сам оформляет заказ и платит.
2. **Секреты не проходят через чат.** Токен бота, пароли, коды входа человек вводит **в своём терминале** скрытым вводом (готовые команды ниже). Если он всё-таки вставил секрет в чат — не используй его. Попроси отозвать (BotFather → `/revoke`) и выпустить новый.
3. **Публичный SSH-ключ (`.pub`) показывать можно, приватный — никогда.** Не печатай, не копируй в чат и не отправляй файл без `.pub`.
4. **Ничего необратимого без «да».** Переустановка сервера, удаление файлов, отключение защиты — сначала одной строкой скажи, что сделаешь и чем это грозит.
5. **Не отрезай себе доступ.** Вход по паролю закрывай только после того, как вход по ключу проверен (скрипт `01-bootstrap.sh` это проверяет сам).
6. **Говори с человеком просто.** Он не программист. Одна инструкция — одно действие, кнопки в кавычках, как на экране. Термин — с пояснением в скобках при первом упоминании. Перед долгим шагом скажи, сколько ждать.
7. **Скрипты — с переменными, без выдумок.** Не меняй логику скриптов без причины. Упал шаг — прочитай ошибку, исправь причину, перезапусти: все скрипты можно запускать повторно.

### Какую свободу получит помощник на сервере

Помощник работает **автономно**. Обычные действия он делает сам, без вопросов-подтверждений. Опасные — только после «да, делай» от человека. Страховка автономии: защитный хук `bash-guard` (блокирует опасные команды даже в режиме без подтверждений) и пользователь без прав администратора. Этот список зашит в `CLAUDE.md` и `style.md` помощника, перескажи его человеку при сдаче.

| Делает сам | Спрашивает «да, делай» |
|---|---|
| файлы и папки в `~/Мозг` | 💳 оплата, покупки, подписки, платные генерации |
| установка программ и скиллов в свою папку | 🗑 удаление данных и необратимые операции |
| настройка себя: плагины, MCP, свои службы, перезапуск | ✉️ отправка сообщений и писем от имени человека |
| код, сайты, скрипты, локальные коммиты | 📢 публикация: соцсети, сайт на основной адрес (прод) |
| поиск, ресёрч, расшифровка, тексты, правки | 🔐 изменения доступа и безопасности (SSH, файрвол, кто пишет боту) |
| — | 🔑 секреты вводит **только человек** сам, скрытым вводом |

Обозначения ниже:
- `KEY` — путь к приватному SSH-ключу на компьютере человека (например `~/.ssh/assistant_server`);
- `IP` — адрес сервера;
- `ADMIN` — пользователь с правами администратора (`ubuntu` на OVH, `admin`, если провайдер дал только root);
- `AGENT` — пользователь помощника без прав администратора (по умолчанию `assistant`).

## 2. Выбор сервера

**Характеристики:** минимум **4 ядра (vCPU), 8 ГБ памяти, 80 ГБ диска**, лучше **6 ядер, 12 ГБ**. Система — **Ubuntu 24.04**. Регион — ближайший к человеку из доступных: Европа (Германия, Франция, Польша, Финляндия) обычно лучше всего.
Почему так много: Claude Code, Telegram-бот, расшифровка голосовых и браузер для скриншотов одновременно съедают 4–6 ГБ. Видео рендерится только на процессоре, без видеокарты. На 2 ГБ или 4 ГБ бот будет падать.

|---|---|---|---|
| **OVHcloud** (ovhcloud.com → VPS) | **VPS-3**: 6 vCPU / 12 ГБ / 100 ГБ NVMe, ≈ $14–15/мес | Лучшее соотношение цены и мощности, надёжный, бэкап недорого, трафик без лимита | Новый заказ иногда проходит ручную антифрод-проверку от 1 часа до 2 суток, бывает и отмена заказа. **Как рекомендовать:**

Предложи 1–2 варианта с ценой в месяц и своей рекомендацией. Жди выбора.

## 3. SSH-ключ на компьютере человека

SSH-ключ — это пара файлов: «замок» (публичный, `.pub`) ставится на сервер, «ключ» (приватный) остаётся только у человека. По нему вход на сервер без пароля.

Создай ключ сам (проверь сначала, что файла ещё нет — чужой ключ не перезаписывай):
- **Mac / Linux:** `ssh-keygen -t ed25519 -f ~/.ssh/assistant_server -N "" -C "assistant-server"`
- **Windows (PowerShell):** `ssh-keygen -t ed25519 -f "$HOME\.ssh\assistant_server" -N '""' -C "assistant-server"`

Ключ без пароля нужен, чтобы ты мог подключаться без вопросов. Скажи человеку одной строкой: файл `~/.ssh/assistant_server` никому не отдавать, а кто его получит, тот сможет войти на сервер.
Покажи человеку содержимое `assistant_server.pub` (одна строка `ssh-ed25519 AAAA… assistant-server`). Он вставит её при заказе сервера.

## 4. Покупка сервера (руками человека)

Дай пошаговую инструкцию под выбранного провайдера: регистрация → подтверждение почты → выбор тарифа → регион → **образ Ubuntu 24.04** → **SSH-ключ** (вставить строку `.pub`) → срок «помесячно» → оплата. Перед оплатой человек называет тебе итоговую сумму. Если она заметно выше ориентира (+30% и больше), разберитесь, что добавилось: лишние опции, годовая оплата, Windows-лицензия.

Особенности:
- **OVH:** после выдачи придёт письмо с IP и пользователем `ubuntu`. Если ключ при заказе добавить не удалось: панель → VPS → «Переустановить» (Reinstall) → Ubuntu 24.04 → вставить SSH-ключ. Предупреди, что переустановка стирает сервер (на новом это не страшно). Проверка заказа может занять до 2 суток, обычно в будни быстрее.
- **Contabo:** в форме заказа есть поле для SSH-ключа, вставь туда. Если его нет, придёт root-пароль, и человек сам в своём терминале положит ключ (команда ниже). Выдают обычно за минуты или часы.
- **Hetzner:** Cloud → проект → «Add Server» → Ubuntu 24.04 → тип → SSH key (вставить) → IPv4 включён → «Create & Buy». Если просит верификацию, человек проходит её сам.

**Если сервер выдан с паролем, а не с ключом**, человек сам запускает в **своём** терминале (пароль вводит он, не ты):
- Mac/Linux: `ssh-copy-id -i ~/.ssh/assistant_server.pub root@IP`
- Windows (PowerShell): `type $HOME\.ssh\assistant_server.pub | ssh root@IP "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"`

Получи от человека **IP-адрес** и запиши в `заметки-настройки.md`.

## 5. Первое подключение и копирование скриптов

Проверь вход по ключу (пользователь — `ubuntu` на OVH, `root` на Hetzner и Contabo):
```bash
ssh -i KEY -o StrictHostKeyChecking=accept-new -o BatchMode=yes <ubuntu|root>@IP 'whoami && lsb_release -ds && nproc && free -g | head -2'
```
Убедись, что это Ubuntu 24.04 и что ядер и памяти столько, сколько оплачено. Если нет — стоп, скажи человеку.

Скопируй скрипты (команда одинаковая для Mac, Windows и Linux):
```bash
scp -i KEY -r scripts <ubuntu|root>@IP:/tmp/assistant-kit
```

## 6. Защита и базовая установка — `01-bootstrap.sh` (≈10–15 мин)

Скрипт: создаёт админа (если был только root), закрывает вход по паролю и под root, включает файрвол (снаружи открыт только SSH), fail2ban (бан за подбор пароля), подкачку, автообновления безопасности, часовой пояс. Ставит Node.js, GitHub CLI, ffmpeg, cmake. Создаёт пользователя помощника **без прав администратора** и ставит в нём Claude Code, Bun и Chromium.

Запускай в фоне на сервере, потому что шаг долгий, а соединение может оборваться:
```bash
# OVH (вход ubuntu):
ssh -i KEY ubuntu@IP "sudo bash -c 'nohup env AGENT_USER=assistant TIMEZONE=<Зона/Город> bash /tmp/assistant-kit/01-bootstrap.sh > /tmp/bootstrap.log 2>&1 < /dev/null &'"
# Hetzner / Contabo (вход root):
ssh -i KEY root@IP "nohup env AGENT_USER=assistant TIMEZONE=<Зона/Город> bash /tmp/assistant-kit/01-bootstrap.sh > /tmp/bootstrap.log 2>&1 < /dev/null &"
```
`TIMEZONE` — например `Asia/Almaty`, `Asia/Bishkek`, `Asia/Tashkent`, `Europe/Moscow`.
Раз в минуту смотри `tail -n 5 /tmp/bootstrap.log`. Шаг закончен, когда в логе появилось `==> Готово` или `ОШИБКА`.

После него:
- **Под root больше не войти.** Дальше `ADMIN` — тот, кого назвал скрипт (`ubuntu` или `admin`).
- Проверь оба входа:
  `ssh -i KEY ADMIN@IP 'sudo -n true && echo admin-ok'` и `ssh -i KEY AGENT@IP 'whoami'`.
- Скопируй скрипты помощнику: `scp -i KEY -r scripts AGENT@IP:~/assistant-kit`.

Все следующие шаги на сервере — под `AGENT`, кроме тех, где прямо сказано «под ADMIN».

## 7. Защита памяти — `02-heavy.sh` (1 мин, обязательно)

```bash
ssh -i KEY AGENT@IP 'bash ~/assistant-kit/02-heavy.sh'
```
Что делает: включает правило «при нехватке памяти падает только виновник», создаёт отсек `heavy.slice` с потолком 40% памяти и команду `heavy`. Зачем: рендер видео вместе с расшифровкой голосового может съесть всю память, и тогда система убивает бота целиком. С `heavy` умирает только тяжёлая задача, а бот остаётся на связи.
Скрипт сам проверяет себя. Строка `ПРОВЕРКА ОК` обязательна: без неё дальше не иди.

## 9. Вход в Claude на сервере (руками человека, 3 мин)

Помощник работает от подписки человека. Вход делает сам человек в **своём** терминале: так код входа не проходит через чат.

Скажи ему:
1. Открой новое окно терминала (Mac: «Терминал», Windows: «PowerShell»).
2. Вставь команду и нажми Enter:
   `ssh -t -i ~/.ssh/assistant_server assistant@IP ~/.local/bin/claude`
   (на Windows: `ssh -t -i $HOME\.ssh\assistant_server assistant@IP ~/.local/bin/claude`)
3. Выбери тему (Enter). Способ входа — **«Claude account with subscription»** (Pro/Max).
4. Появится ссылка. Открой её в браузере, войди **своей** почтой с подпиской, нажми «Authorize».
5. Скопируй код со страницы и вставь в терминал, Enter.
6. Если спросит про доверие к папке — «Yes». Увидишь приглашение Claude — напиши `/exit`, окно можно закрыть.

Проверь сам:
```bash
ssh -i KEY AGENT@IP 'export PATH=$HOME/.local/bin:$PATH; timeout 90 claude -p "ответь одним словом: ок" --model haiku'
```
Ответ «ок» — вход есть.

## 11. Telegram-бот

### 11.1 Подготовка на сервере
```bash
ssh -i KEY AGENT@IP 'bash ~/assistant-kit/05-bot-setup.sh'
```
Создаёт `~/assistant/` (запуск бота, сохранение ключа, захват владельца, стиль общения `style.md`) и службы `assistant.service` и `assistant.timer` (каждые 5 минут поднимают бота, если он упал). Пока службы выключены.
Если подписка **Max**, можно поставить Opus: `ssh -i KEY AGENT@IP 'echo opus > ~/.config/assistant-model'`.

### 11.2 Человек создаёт бота (3 мин)
Скажи ему:
1. В Telegram найди **@BotFather** (с синей галочкой), нажми «Старт».
2. Отправь `/newbot`.
3. Название — как бот будет подписан в чатах, например «Мой помощник».
4. Адрес — латиницей, без пробелов, в конце обязательно `bot`, например `ivan_helper_bot`. Если занято — добавь цифру.
5. BotFather пришлёт строку вида `123456789:AAH…`. Это **ключ бота**, он работает как пароль. **Не присылай его мне в чат.**

### 11.3 Человек сохраняет ключ на сервере (1 мин)
Он вставляет ключ в своём терминале, символы не видны:
```
ssh -t -i ~/.ssh/assistant_server assistant@IP '~/assistant/save-token.sh'
```
(Windows: `ssh -t -i $HOME\.ssh\assistant_server assistant@IP '~/assistant/save-token.sh'`)
Скажи: «Вставь ключ, нажми Enter. Потом удали сообщение с ключом в чате BotFather».

### 11.4 Владелец — только он
1. Человек пишет своему боту в Telegram «привет». Бот пока молчит, так и должно быть.
2. Ты запускаешь:
   ```bash
   ssh -i KEY AGENT@IP '~/assistant/capture_owner.py --wait 600'
   ```
   Скрипт находит, кто написал, и записывает его числовой Telegram ID в список разрешённых (`allowlist`). Остальным бот не отвечает. Если боту писали несколько человек, скрипт ничего не запишет: уточни, кто владелец.
3. Включи бота:
   ```bash
   ssh -i KEY AGENT@IP 'systemctl --user enable --now assistant.timer && systemctl --user start assistant.service && sleep 20 && tmux capture-pane -p -t assistant-telegram | tail -20'
   ```
4. Попроси человека написать боту ещё раз: «Привет! Расскажи, что ты умеешь». Ответ должен прийти за 10–30 секунд. Потом пусть пришлёт короткое голосовое: бот должен ответить по сути сказанного.

Как устроено (если придётся чинить):
- Бот — это сессия Claude Code в `tmux` с именем `assistant-telegram`, запущенная из `~/Мозг` с флагом `--channels plugin:telegram@claude-plugins-official`.
- Плагин Telegram **глобально выключен** и включается только в этой сессии. Иначе любая другая сессия Claude на сервере перехватывала бы бота.
- `claude-mem` в сессии бота по умолчанию выключен: его старт на каждом сообщении может тормозить или ронять канал. Помощник пользуется им в других сессиях. Попробовать в боте: `echo CLAUDE_MEM_IN_BOT=true >> ~/.config/assistant.env && restart-bot`. Если бот после этого замолчал, верни `false`.
- Бот работает в автономном режиме (`--dangerously-skip-permissions`; в остальных сессиях на сервере — `defaultMode: bypassPermissions` в `~/.claude/settings.json`): обычные действия делает сам, на опасное спрашивает «да, делай» в чате (список в разделе 0). Без хука `bash-guard` `start-bot.sh` бота не запустит. Хук не отключать: он и есть страховка автономии.
- Перезапуск (например, после нового плагина или MCP, которые подхватываются только при старте): `restart-bot`.
- Посмотреть экран бота: `tmux capture-pane -p -t assistant-telegram`. **Не запускай `start-bot.sh` напрямую из своей сессии Claude:** он унаследует её переменные. Только через `systemctl --user start assistant.service`.

Сервер появится в приложении Claude (телефон или компьютер, раздел Code) как машина, на которой можно открыть полноценную сессию.

```bash
ssh -i KEY AGENT@IP 'SERVER_NAME="Сервер <Имя>" bash ~/assistant-kit/06-remote-control-optional.sh'
```
Если на экране вопрос (включить Remote Control, доверять папке), человек отвечает в своём терминале: `ssh -t -i KEY assistant@IP 'tmux attach -t claude-rc'`, ответить, выйти `Ctrl+B`, потом `D`.

## 13. По желанию: Tailscale и браузер сервера

**Tailscale** — личная закрытая сеть между сервером и устройствами человека. С ней помощник может показать на телефоне сайт в разработке или страницу на сервере, не открывая сервер в интернет.
1. Человек ставит приложение Tailscale на телефон и компьютер и входит (Google, Apple или Microsoft).
2. Ты (под ADMIN):
   ```bash
   ssh -i KEY ADMIN@IP 'sudo AGENT_USER=assistant bash /home/assistant/assistant-kit/07-tailscale-optional.sh'
   ```
   Скрипт напечатает ссылку входа. Человек открывает её и входит тем же аккаунтом, что в приложении.
3. После этого помощник сам публикует свои страницы в личную сеть: `tailscale serve --bg <порт>`. Порты в файрволе **не открывай**.

**Браузер сервера с входами** (чтобы помощник работал в кабинетах сайтов от имени человека) — продвинутая опция. Делай только по прямой просьбе. Рецепт: под AGENT, без прав администратора, службами `systemctl --user`: виртуальный экран (Xvfb или Xvnc) → Chromium из `~/.cache/ms-playwright` с отдельным профилем и `--remote-debugging-port=9222` на 127.0.0.1 → noVNC на 127.0.0.1:6080 с паролем → `tailscale serve` → человек открывает страницу на телефоне и сам входит в нужные сайты. Добавь MCP `@playwright/mcp --cdp-endpoint http://127.0.0.1:9222`, чтобы помощник управлял этим браузером. Учти: в профиле лежат входы человека. Браузер ест 1,5–3 ГБ, поставь ему потолок памяти (`systemctl --user set-property <служба> MemoryMax=…`).

## 14. Финальная проверка и сдача

```bash
ssh -i KEY AGENT@IP 'bash ~/assistant-kit/check.sh'
```
Не должно быть ни одного ❌ (⚪ — необязательное). Потом руками с человеком:

- [ ] Бот отвечает владельцу на «привет» за ≤30 секунд.
- [ ] С **другого** аккаунта Telegram бот молчит (если у человека есть второй аккаунт или телефон друга).
- [ ] Голосовое расшифровано, ответ по сути.
- [ ] Фото и файл, отправленные боту, лежат в `~/Мозг/Входящие/`.
- [ ] Бот присылает файл: «Сделай короткий PDF с планом на неделю и пришли».
- [ ] Перезагрузка выдержана: `ssh -i KEY ADMIN@IP 'sudo reboot'`, через 2–3 минуты бот снова отвечает (поднимается сам через `assistant.timer`).
- [ ] С компьютера человека: `ssh -i KEY root@IP` → отказ, `ssh -o PubkeyAuthentication=no ADMIN@IP` → отказ (пароли закрыты).
- [ ] `~/.claude/CLAUDE.md` заполнен (нет `{{`), `~/Мозг/ПРАВИЛА.md` на месте.
- [ ] В чатах с ИИ нет ни одного секрета (токен бота, пароли).

**Сдача человеку.** Напиши коротко, простыми словами:
1. Что готово: бот @…, сервер (провайдер, тариф, цена в месяц, дата продления), что умеет.
2. Как пользоваться: писать боту как человеку, слать голосовые и файлы, просить «запомни», «сделай», «найди».
3. Что лежит у него: ключ `~/.ssh/assistant_server` (не терять и не отдавать), а `заметки-настройки.md` хранить у себя.
4. Первые идеи, что попросить у бота (3–5 штук под его работу из шага 1).
5. Деньги: продление сервера каждый месяц, подписка Claude. Если карта не пройдёт, сервер выключат примерно через неделю, а данные удалят.

## 15. Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `Permission denied (publickey)` | Не тот ключ или пользователь. Проверь `-i KEY` и имя (`ubuntu`/`admin`/`assistant`; root после шага 6 закрыт) |
| Скрипт упал на `apt` (lock) | Сразу после выдачи сервер сам ставит обновления. Подожди 3–5 мин и запусти повторно |
| `ПРОВЕРКА НЕ ПРОШЛА` в 02-heavy | Нет systemd-сессии пользователя: убедись, что 01 включил linger (`loginctl show-user assistant -p Linger`), переподключись под AGENT и повтори |
| Бот молчит | `tmux ls` (есть ли сессия?) → `tmux capture-pane -p -t assistant-telegram` (что на экране?) → `restart-bot`. Частые причины: вход в Claude истёк (повторить шаг 9), ключ бота отозван (11.3), плагин telegram включён глобально (`claude plugin disable telegram@claude-plugins-official`) |
| Бот отвечает с паузой в минуту и больше | Сервер перегружен (`htop`). Возможно, идёт рендер без `heavy`. Проверь, что `claude-mem` в боте выключен |
| Код 137 у задачи | Не хватило памяти в отсеке `heavy`. Запусти задачу одну или с `--workers 1` |
| `OAuth session expired` | Вход в Claude протух. Человек повторяет шаг 9 в своём терминале |
| Заказ OVH долго «на проверке» или отменён | Это антифрод, не ошибка человека. Подождать до 48 ч или написать в поддержку. Если срочно — Contabo |
| Hetzner просит верификацию | Человек проходит её сам (документ или карта). Сервер не создавать, пока не подтвердили |

## 16. Обслуживание (расскажи человеку в конце)

- Система обновляет безопасность сама. Раз в месяц можно попросить бота: «проверь сервер: место на диске, память, обновления». Если нужен перезапуск после обновления ядра, бот подготовит команду, а ADMIN сделает `sudo reboot`.
- Claude Code обновляется сам. Если бот после обновления повёл себя странно — `restart-bot`.
- Бэкап: у OVH и Hetzner есть платные автоматические снимки (≈ $1–3/мес), их стоит включить. Ценное из `~/Мозг` бот может раз в неделю складывать в приватный репозиторий GitHub (по просьбе, с `gh auth login`, вход — по ссылке).
- Новые возможности: «найди скилл для …» (через find-skills, только бесплатные и публичные), подключение сервисов (Google, Notion и т.п.) — бот ведёт по шагам, ключи только скрытым вводом в `~/.config/<сервис>/*.env` с правами 600.
